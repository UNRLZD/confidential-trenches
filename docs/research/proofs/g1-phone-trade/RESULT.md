- A live trade that reports ok counts as filled only when its signature read back from Node at commitment finalized with no error and the record's wallet as fee payer on both RPCs below (a provider that answers null is shown as `missing at finalized` and the read is unread), and that wallet was funded by the pinned wallet 0 (`--wallet0`, never the file's own claim; the file must name it too) in a System transfer both RPCs return at commitment finalized; one that does not counts as a failed trade (in n, not in ok, infinite in `total`) and is listed as not counted as filled.
- A null reply at finalized is not a chain fact (the tx may not be final yet, or the RPC lacks old history): in a trade's read-back, a null on either provider makes that read unread, so no verdict rests on one provider; in a funding read, a null for any signature of the wallet's list makes that provider's funding read unread, and so does a list cut at 100 signatures (the read is not paged) with no funding transfer from wallet 0 in it; a cut list that has one keeps the funding, and its returns are marked as possibly incomplete.
